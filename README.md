# ❄️ HVACR Enterprise User Journey & REST API

โปรเจกต์นี้คือระบบ Web Application แบบ Full-Stack ที่จำลองพฤติกรรมและเส้นทางการใช้งานของลูกค้า (User Journey) ในธุรกิจเครื่องปรับอากาศ (HVACR) ตั้งแต่การค้นหาสินค้า ไปจนถึงการจองคิวรับบริการและรีวิวหลังการขาย โดยแยกโครงสร้างการทำงานระหว่าง Frontend และ Backend อย่างชัดเจน

---

## 💻 1. ส่วนของหน้าเว็บ (Frontend Architecture)
หน้าเว็บถูกพัฒนาให้อยู่ในรูปแบบ Single Page Application (SPA) ที่ตอบสนองรวดเร็วและสวยงาม
*   **UI/UX Design:** ออกแบบโดยใช้กรอบการทำงาน Tailwind CSS พร้อมใส่ลูกเล่นความสวยงามแบบโปร่งแสง (Glassmorphism) บนพื้นหลังโทนสีเข้ม
*   **Typography:** ใช้ฟอนต์ภาษาไทยจาก Google Fonts ได้แก่ 'Sarabun' สำหรับเนื้อหาหลัก และ 'Kanit' สำหรับหัวข้อ
*   **ระบบ 5 ขั้นตอน (User Journey 5 Steps):**
    1.  **Awareness & Research (การรับรู้และการค้นหา):** ระบบแคตตาล็อกสินค้าเครื่องปรับอากาศและอุปกรณ์ติดตั้งกว่า 50 รายการ พร้อมช่องค้นหาแบบ Real-time และปุ่มเพิ่มลงตะกร้า
    2.  **Consideration (การพิจารณา):** ตารางเปรียบเทียบสเปกเครื่องปรับอากาศ (BTU), ราคาจำหน่าย, ค่าติดตั้ง และระยะเวลารับประกัน
    3.  **Purchase & Install (การซื้อและการติดตั้ง):** ระบบตะกร้าสินค้า (Shopping Cart) พร้อมฟอร์มกรอกที่อยู่จัดส่งแบบละเอียด และตัวเลือกช่องทางการชำระเงิน
    4.  **Usage & Maintenance (การใช้งาน & บำรุงรักษา):** หน้าปัดจำลองสถานะการทำงานของแอร์ผ่าน IoT (อุณหภูมิ, สถานะคอมเพรสเซอร์, ค่าไฟ) และระบบจองคิวช่างล่วงหน้า 6 เดือน **ที่สามารถส่งอีเมลแจ้งเตือนไปยังผู้ใช้งานได้จริง**
    5.  **Loyalty & Advocacy (ความภักดี & บอกต่อ):** ระบบฟอร์มให้คะแนนความพึงพอใจแบบดาว (Star Rating) และกระดานแสดงความคิดเห็นจากลูกค้า

## ⚙️ 2. ส่วนของเซิร์ฟเวอร์ (Backend Architecture)
ระบบหลังบ้านพัฒนาด้วย Node.js และเปิดพอร์ตให้บริการ API ผ่าน Express.js โดยมีการเชื่อมต่อกับฐานข้อมูล NoSQL และระบบความปลอดภัย ดังนี้:
*   **ระบบฐานข้อมูล (Database):** ใช้ MongoDB Atlas ร่วมกับไลบรารี `mongoose` ในการกำหนดโครงสร้างข้อมูลผู้ใช้งาน (User Schema) ซึ่งประกอบด้วย username, password, email และ role
*   **ระบบรักษาความปลอดภัย (Security):** 
*   รหัสผ่านผู้ใช้จะถูกเข้ารหัสก่อนบันทึกลงฐานข้อมูลด้วย `bcryptjs`
*   ใช้ `jsonwebtoken` (JWT) ในการสร้าง Token สำหรับยืนยันสิทธิ์การเข้าถึง API เส้นทางต่างๆ
*   **ระบบส่งอีเมล (Email Service):** ติดตั้งแพ็กเกจ `nodemailer` เวอร์ชัน 6.9.14 เพื่อเชื่อมต่อกับเซิร์ฟเวอร์ SMTP ของ Gmail สำหรับยิงอีเมลแจ้งเตือนการจองคิวอัตโนมัติ

**API Endpoints ที่สำคัญ:**
*   `POST /register` - สมัครสมาชิกใหม่ 
*   `POST /login` - เข้าสู่ระบบและรับ JWT Token
*   `GET /users` - ดึงรายชื่อผู้ใช้งานทั้งหมด (พร้อมระบบ Pagination)
*   `POST /send-booking-email` - ส่งอีเมลยืนยันการจองคิว (ต้องแนบ Token เพื่อใช้งาน)

## 🚀 3. วิธีการติดตั้งและการใช้งาน (Deployment Guide)

โปรเจกต์นี้ถูกออกแบบมาให้สามารถนำไปรันบนระบบ Cloud ได้ฟรี 100% 

### 🗄️ ขั้นตอนที่ 1: การตั้งค่าฐานข้อมูล (MongoDB Atlas)
1. สมัครใช้งาน MongoDB Atlas และสร้าง Cluster ใหม่
2. สร้าง Database User และจดรหัสผ่านไว้
3. ไปที่เมนู **Network Access** แล้วตั้งค่า IP Access List เป็น `0.0.0.0/0` (Allow Access From Anywhere) เพื่อให้เซิร์ฟเวอร์คลาวด์สามารถเชื่อมต่อได้
4. คัดลอก Connection String (`mongodb+srv://...`) เพื่อนำไปใช้ในขั้นตอนต่อไป

### ☁️ ขั้นตอนที่ 2: การฝากเซิร์ฟเวอร์ (Render.com)
1. นำไฟล์โค้ด Backend ทั้งหมดอัปโหลดขึ้น GitHub (ห้ามอัปโหลดโฟลเดอร์ `node_modules`)
2. เข้าสู่ระบบ Render.com แล้วเลือกสร้าง **Web Service** ใหม่
3. กำหนดค่า Build Command เป็น `npm install` และ Start Command เป็น `node server.js`
4. ใส่ Environment Variables ที่จำเป็น ได้แก่ `MONGO_URI`, `JWT_SECRET`, `EMAIL_USER`, และ `EMAIL_PASS`
5. กด Deploy และรอจนสถานะขึ้นเป็น **Live** จะได้ลิงก์ URL ของ API มาใช้งาน

### 🌐 ขั้นตอนที่ 3: การเชื่อมต่อหน้าเว็บ (GitHub Pages)
1. นำไฟล์ `index.html` ไปฝากไว้บน GitHub Repository ของส่วน Frontend
2. แก้ไข URL ภายในฟังก์ชัน `fetch()` ให้ชี้ไปยังลิงก์ API ของ Render.com ที่ได้จากขั้นตอนที่ 2
3. ไปที่เมนู Settings > Pages ใน GitHub เพื่อเปิดใช้งาน GitHub Pages

# 2. เริ่มต้นการทำงานของเซิร์ฟเวอร์
